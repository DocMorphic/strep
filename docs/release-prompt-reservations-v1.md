# Reserved prompts for future release evaluation

The release matrix still lacks concrete held-out fixtures. Before using more development examples as release evidence, a recorded-exposure inventory scanned report request/protocol JSON and benchmark JSON. The first snapshot contains 2,152 files, 113 normalized prompt-like strings and 25 integer seeds, with no parse errors. It is a dated inventory of recorded data, not proof that every historical or model-training example is known.

`benchmarks/release-prompt-reservations-v1.json` reserves six compositions for each of the twelve existing action families: 72 scenario prompts, each with five seeds not found in the snapshot. All 72 pass an exact normalized-text/seed overlap screen. Normalization catches capitalization, punctuation, whitespace and Unicode-width variants; it does not establish semantic novelty. The checkpoint's training-set overlap remains unknown.

The set includes locomotion, parkour, ground recovery, combat, gestures, dance, everyday tasks, object manipulation, partner interaction, environment traversal, aerial/nonwalking motion and style/capability comparisons. Categories remain evaluation strata, never a supported-action whitelist. Partner scenarios describe both people; actor-specific compilation and placements still need to be frozen. Style cases need paired control levels. Object/terrain/water/hanging cases need the actual required geometry and context.

No reserved prompt has been generated as part of this work. Do not use these prompts or seeds to tune the solver. If a reservation is used during development, retain that fact and retire/version it before release trials. Refresh the inventory immediately before executing a frozen release candidate.

The inventory accepts one explicit `--reservation` catalog exemption so that the unexecuted reservation file itself does not count as a generation record. It permits only an unexecuted reservation JSON under benchmarks. Report records remain included, so actually using a reserved prompt in a recorded run still exposes the overlap. The checker permits only its own byte-identical catalog exemption. Ten tests pass across normalization, nested provenance, seed reuse, family coverage, duplicate cases and exemption restrictions.

The 72 prompts are only reserved inputs, not a release-ready fixture set. Concrete held-out rigs, object geometry and partner pairings remain unbound. Transition, style, force/balance and joint-dynamics acceptance criteria still need calibration and freezing. The method/checkpoint/baseline must be frozen before trials; development review does not replace the independent animator and timed-cleanup requirements. No release gate is promoted, and `held_out_fixtures` remains unset until this full package is ready.
