# Complete proposal values with derivatives on demand

Nonlinear SLSQP proposals previously built a complete constraint Jacobian on every value query, including discarded line-search points. The objective supplied value and gradient together through `jac=True`; constraint value callbacks used the same eager query. `protected_inequality_step.fit` now separates scalar objective and gradient callbacks, measures the complete nonlinear row population for each queried control, and computes the full Jacobian when a gradient or constraint-Jacobian callback requests it.

The single-point cache binds exact bounded controls to detached measured values and, when requested, their checked derivatives. A derivative must have the complete original shape, finite entries and values matching the independently measured population. Repeated value/gradient callbacks at the same point reuse the cache. Objective, headroom, control bounds, trust box, feasible/protected rows, saved-representation checks and final nonlinear retention gates remain unchanged. Value-only queries stay explicitly unretained. Budget expiry between value and gradient callbacks returns the last retained point; it never promotes a solver query.

Cached values are copied before a later derivative callback can reuse or alter measurement storage. This prevents matching a changed derivative population against an aliased, already-mutated measurement. A test deliberately reproduces that failure. Explicit clipping uses the same controls for objective, constraints and derivatives, including callbacks just beyond a floating-point bound.
