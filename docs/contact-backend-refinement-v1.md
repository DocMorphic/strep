# Explicit-backend contact refinement

`scripts/contact_backend_refinement.py` exposes a separate experimental command for refining an already checked, serialized native baseline. It requires an explicit `continuous-native` or `stored-native` proposal backend. The first uses the existing continuous native differences; the second uses [Float32 stored-key native differences](stored-native-coupled-contacts-v1.md). Both keep continuous contact guidance. Neither changes Studio defaults or the historical warm producer.

```powershell
python scripts/contact_backend_refinement.py CONTACTS PERMISSIONS SURFACE_POLICY GEOMETRY_POLICY FRESH_OUTPUT --proposal-backend stored-native --start-controls RETAINED_CONTROLS --iterations 2 --backoffs 5 --trust 0.005 --difference-step 0.001 --phase-seconds 120 --maximum-iterations 200
python scripts/verify_contact_backend_refinement.py FRESH_OUTPUT FRESH_REPLAY_OUTPUT
```

The positional inputs are the existing source-bound scene-contact, edit-permission, surface-policy and full sampled-geometry contracts. Retained controls remain relative to the original curves and caps. Omitting the backend rejects at argument parsing; invalid API backend values reject before reading inputs or creating outputs. The command records the backend, qualified factory class, native/contact probe provenance, source inputs, original caps/clocks, methods, solver settings, complete affine proposals and every exported rejection. Choosing a stored-key stencil does not certify nonlinear feasibility or a uniform quantization error bound.

Every candidate still passes through the strict complete-affine selector, actual serialized curve/static audits, complete independently decoded native/contact conditions, and individual no-regression guards. Intermediate progress is provisional. A new retained improvement requires the unchanged complete sampled-geometry audit; failed, stalled or timed-out proposals preserve the serialized starting controls and files. Keeping an earlier improvement is not counted as new work. The caller remains responsible for supplying an already checked baseline and for engine and human validation.

The separate verifier reconstructs original caps and editable keys, redecodes every closed population, recalculates scalar/vector native arithmetic and uncached full surface contacts, checks paired guards and saved Jacobians, replays the entire affine selection and all export decisions, and reruns every declared final geometry query when eligible. It verifies the selected backend and factory against each model's native/contact stencil metadata. Hashes alone cannot make altered observations consistent with those reductions. Decoder and geometry kernels are shared with the producer; derivative columns are checked as saved evidence rather than all remeasured. This establishes neither continuous collision nor engine, semantic, animator or release quality.

An isolated source copy passed **107 checks in 289.46 seconds**, including **37 new command/replay tests**, 28 stored-native model tests and 42 existing warm producer/replay tests. Both backends exercise serialized-start preservation, actual two-iteration fixture progress with complete tiny geometry and independent replay, failed-geometry fallback, worker/output exclusion, explicit metadata and rejection of rebound numeric or backend claims. An actual small CPU conic path is also covered. Fixtures use synthetic curves and establish no production improvement. The first fixture attempt failed six independent replay checks because its injected proposal bypassed the strict affine selector; those outputs remain archived locally, and the tests now exercise the real selector.
