# Saved Studio requests while memory is unavailable

Studio now saves a generation request before starting its model stages. `/api/jobs` launches the lightweight admission supervisor and returns `waiting_resources`. A request that cannot obtain sampled headroom within the admission deadline becomes `deferred`, with no model child started. Activity shows that distinction, preserves the current preview, and offers **Retry saved request**. Retry creates a fresh job linked to the original and copies its exact descriptions, segment durations, seeds, movement profile and constraints; edits to the current composer do not change it.

The generation estimate is **4 GiB process-tree RSS**. It includes margin above the largest of 28 saved generation-job peaks, 3,468,222,464 bytes. With the existing 600 MiB reserve, admission requires **4,924,112,896 bytes** available across 15 sampled seconds, within a 60-second deadline. This is an empirical estimate for the current generation pipeline, not a model memory guarantee or a training/contact/engine profile. The outer supervisor keeps the 600 MiB available-RAM floor, 7 GiB process-tree RSS cap and 3,600-second whole-job execution cap. Existing stage guards and the model worker lock remain active. GPU/VRAM admission remains unimplemented.

The request is stored in `resource-request.json`, separately from the pipeline's working `request.json`. A launch record binds its file hash, resolved movement controls and selected request/pipeline source archives. The worker checks these bindings after admission, before importing the pipeline. Changed queued inputs or selected implementation cannot silently execute. Historical status checks use the archive; retry checks current control resolution. This is not a complete environment/dependency attestation.

Live supervisor identity uses PID and process creation time, including after a server restart. Unknown liveness stays unverified; a reused PID cannot keep a dead job active. A deferred or failed guard overrides stale native completion and output files. Guard completion alone cannot make a motion result ready. Malformed generation state stays local to that job. Only a deferred request whose model child never started is eligible for this retry action; failed or partially executed work remains preserved separately.
