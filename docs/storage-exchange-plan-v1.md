# Exchange absolute storage choices without increasing the budget

The stored-motion study reaches its original limit of 64 changed quaternion components while one motion-rate failure remains. Adding a 65th correction is outside that policy. The new `native_storage_exchange_plan` enumerates proposals that restore one existing component before adding another. Existing-identity reversal/restoration and additions below capacity remain direct proposals. Every step is an absolute neighboring Float32 choice; steps never accumulate.

The planner preserves the supplied rate-option order and enumerates every current restoration for each new option at capacity. It counts the complete population before construction and rejects insufficient budgets instead of returning a filtered prefix. Applying a proposal copies its inputs, checks the exact restoration against the current correction list, and verifies the final correction count. It does not bind the full authoring context or verify key permissions; the original source-bound editor and export audit remain required.

All 38 isolated public-source tests pass without skips. They include the full 64-choice boundary, complete 128-proposal enumeration, malformed and stale proposals, complete-budget rejection, copies, and a procedural GLB export. The GLB check confirms that the old component returns to its nearest stored value and exactly one new component becomes its declared neighbor. This confirms proposal/storage behavior, not a motion repair, scene acceptance or release approval.

A separate bounded exchange study and manual reader are prepared locally. They retain complete option/proposal plans and all failed exports, test at most 64 proposals, and require all original motion, material, clearance, contact, reference, edit and trust gates. The full original scene scan remains conditional on those gates. The study has not run at publication; this source milestone makes no feasibility or quality claim. All fourteen release evidence arrays remain empty.
