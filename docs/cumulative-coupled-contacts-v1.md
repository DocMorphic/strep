# Repeated source-relative contact correction

`scripts/cumulative_coupled_contacts.py` is an offline command for repeated native/contact proposals followed by one complete sampled geometry audit. It accepts the existing source-bound scene, native edit permissions, surface-contact policy and geometry policy. It uses the original loaded rig, all supplied skin influences and declared object/partner targets; action names do not select a different implementation.

```powershell
python scripts/cumulative_coupled_contacts.py contacts.json permissions.json surface-policy.json geometry-policy.json reports/cumulative-contacts-v1 --iterations 3 --phase-seconds 120 --maximum-iterations 200
```

An optional `--start-controls source-relative-controls.npy` supplies cumulative normalized controls for the same original source and permissions. The command exports and independently decodes the start, checks every original native condition and every original contact no-regression guard, and rejects an invalid start. It does not treat a supplied vector as an already approved animation. `--geometry-donor reports/previous-cumulative-run/geometry` can reuse a complete cache from the exact-input geometry API; legacy archives lack the required full query-input snapshot and cannot be adopted.

The command constructs the source-rate caps once from the original clip before adding the complete geometry clock. It never redefines the source around a provisional candidate. Each iteration rebuilds the full symmetric coupled model around the actual decoded curves, retains all native rows and individual surface guards, and uses the bounded conic solver. Full, half and subsequent powers-of-two backoffs are exported independently. A native excess remains a failure even when very small. Every trial, static audit, model, direction, condition population and rejection is preserved.

An intermediate step requires all native conditions to pass, every surface row to preserve its previous passing/failing bound, a nonincreasing worst contact excess and a strict decrease in squared positive excess. The original contact guards are also rechecked. These steps are explicitly provisional: no intermediate geometry result or retention is invented. A timeout without a direction ends the proposal loop; a prior provisional improvement can still reach the final audit. Defaults allow three iterations, ten backoffs, a 0.02 normalized trust radius and a 0.001 difference step. Explicit limits permit 1-4 iterations, 1-10 backoffs, a 1e-6-0.1 trust radius and a 1e-6-0.01 difference step. Each solver phase accepts 1-300 seconds and 1-500 iterations. Model construction, assembly, serialization and geometry lie outside that phase budget.

The raw numerical solver direction is saved before validation. Its usable direction is projected into the exact intersection of the requested trust step and the original control box; no solver tolerance is added to either. Projection changes are recorded separately, and the original solver report describes the raw direction. If floating addition puts a backoff displacement one ULP outside its exact trust bound, that coordinate moves towards its starting value. A projected direction carries no affine or nonlinear feasibility certificate; the independently exported native/contact conditions still decide provisional progress, followed by final geometry.

Only the final provisional motion receives the complete declared geometry audit. The exact-input cache captures every placed vertex, triangle index, object pose/shape and declared plane at all geometry times, and retains complete numeric evidence. Changed inputs require fresh whole-scene queries. Exact-input reuse preserves failed results as failures. Default archive budgets are 256 MiB per array and 16 GiB total logical bytes; overflow rejects without dropping rows. The command uses the existing one-worker lock and one numerical thread, binds source and method hashes, rejects an existing output folder and detects changes to audited curves or observations. A failed final audit retains the original controls, while preserving all provisional exports for inspection.

The command requires an originally feasible native/contact-position start; it is a surface-contact improvement stage, not a substitute for native feasibility restoration. A retained result can still fail authored surface limits and is marked as a partial improvement. Original selection, engine equivalence, self/continuous collision, semantic realism, developer cleanup review and release approval remain separate. Source-bound arbitrary actions and partner/object declarations are preserved by the workflow, but a synthetic test is not evidence that all action families or real interactions are solved.

All 58 focused workflow cases and 286 isolated workflow/contact/geometry/solver source cases pass without vendor code, models or downloaded characters. Tests independently decode real saved curves and recompute uncached surface observations and whole geometry results; they cover repeated steps, original cap resets, strict native/contact failures, initial seeds, timeouts, failed geometry, altered source/candidate files, complete result inventories and exact donor reuse. A command test invokes the real bounded CPU solver. Most branch tests supply controlled directions to exercise retention decisions; they do not establish general solver convergence. Real-character cumulative correction and production cache parity/performance remain unmeasured until their separate runs complete.
