## What the primary sources establish

[NVIDIA's current model card](https://huggingface.co/nvidia/Kimodo-SOMA-RP-v1.1) describes a single-skeleton generator that does not understand scene objects. Its [official repository](https://github.com/nv-tlabs/kimodo) supplies text/kinematic inference, interactive authoring and benchmark tools. The locally pinned checkout is `58e781898b3d7e328a676a75d3e338c45dce3ad9`; inspection finds no training entry point or optimizer/backward training loop in its motion package. This is a statement about the inspected checkout, not proof that fine-tuning is impossible or that no external trainer exists. A new training workflow would need implementation and validation.

[Uni-Inter](https://arxiv.org/html/2511.13032v1) uses a shared interaction volume for human/object/scene conditioning. Its experiments use 40-frame windows, and its human/object evaluation conditions on supplied object poses rather than generating an object's trajectory. That is relevant precedent, but does not establish Strep's arbitrary-rig asset pipeline, long transitions, calibrated character stats or commercial deployment rights.

[MuJoCo's computation documentation](https://mujoco.readthedocs.io/en/latest/computation/index.html#inverse-dynamics-and-optimization) explains how inverse dynamics can assess prescribed articulated trajectories under an explicit contact model. It requires a multibody model and contact assumptions; it does not infer a person's strength from an animation. [ProtoMotions](https://github.com/NVlabs/ProtoMotions) provides simulated motion-policy training, and NVIDIA documents compatibility with Kimodo exports. Any use here would be an optional offline teacher or diagnostic whose resulting clip is baked to an asset. The product contract remains offline authoring.

## Shortest next experiment

1. Separate incompatible authored targets/contact mechanics from generation and rig-transfer failures. Keep the original benchmark unchanged. New physically compatible targets form a separately versioned development study, never a silent replacement for a failed benchmark.
2. Use the unchanged checkpoint's existing full-body and end-effector controls to test a small scene-conditioned proposal stage. A proposal must pass the same complete stored skin/contact/geometry checks, source preservation and object-force assessment before it can be retained. Passing only target joints or a preview is insufficient.
3. Add an explicit articulated-body diagnostic before mapping gameplay strength/stamina to physical promises. Require declared segment mass/COM/inertia, joint coordinates and limits, support/contact models, external object reactions and capacity provenance. Report sensitivity to assumptions. Unmeasured human capacities remain unknown.
4. If the proposal and deterministic correction baselines still fail, prototype an offline residual editor conditioned on original motion, actual rig proportions, scene geometry, contact timing/targets, object tracks and explicit style/capacity descriptors. Compare a small editor against those baselines before attempting a full generator replacement. This is a research hypothesis, not an implemented feature or a promised remedy.
5. Acquire targeted clean demonstrations through self-capture or separately licensed sources. Record synchronized actor/object/partner tracks, contact surfaces, failed rough input, corrected target, provenance and genuine review. Conditional force positives and synthetic fixture passes are excluded from clean-human training admission. Existing held-out reservations remain untouched.
6. Measure learning curves at increasing admitted episode counts, subject to available data and compute; do not promise that a small set will suffice. Split by action, person/rig, object and partner composition. Compare semantic correctness, contact/penetration, transitions, rig transfer, import success, human ratings and actual cleanup time. Repeat with several fixed seeds and preserve all attempts.

Before acquiring an alternate model or data, inspect its actual code/checkpoint availability, dependency/body-model compatibility, terms and local hardware cost. A paper's article license does not establish checkpoint or training-data rights. This record downloads no model/data, trains nothing, freezes no release gate and grants no capability approval. The owner has chosen developer review first; no genuine ratings or timed cleanup results have yet been recorded.
