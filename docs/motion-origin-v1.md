# Preserve generation intent through character transfer

Studio character transfers now carry the original generation record, action request and resolved movement-profile brief under `source/motion-origin/` in the downloadable character animation package. A manifest binds these exact bytes to the source motion hash. This preserves the original prompts, designer-authored stat rules, resolved text, seed and recorded model/checkpoint identity for later inspection. It does not claim that the animation follows the profile.

Request validation checks that the successful generation record identifies this motion, the retained request and seed agree, and the brief matches both the record and its own resolution checksum. It preserves the recorded compiler output rather than rerunning a newer compiler. Historical absolute paths in the record are data only; the verifier never follows them. A missing record is explicitly `unavailable`; an orphan or mismatched brief is rejected. Fixed filenames, folder containment and a 4 MiB per-metadata-file limit constrain reads.

`studio_characters.prepare_job` rechecks the validated hashes while creating the immutable job snapshot. The worker verifies the copied manifest before export. API results expose the original records with `applies_to: original_source_motion` and `quality_approved: false`. Existing clip-edit source copying preserves the original intent, while the edit recipe records the subsequent change. Original intent is not relabeled as a description or quality rating of the edited output.

Twenty-six focused provenance/character tests pass, including metadata mismatches, changed inputs between validation and copying, missing records, plain clips, inherited snapshots and the existing character/transfer workflow. The live Studio was restarted only after verifying its exact idle process owners; independent solver studies were left running.

The real API verification is `reports/motion-origin-export-v1`. Job `20260928-015236-7ba359be` transfers an existing high-mobility kick to CesiumMan. All 51 source-backed archive entries, four provenance downloads and the package download match. The GLB is byte-identical to the corresponding frozen profile-transfer clip, whose 120-frame, 19-bone engine proof is retained; this comparison does not count it as a new engine run.

The follow-up `reports/motion-origin-edit-v1` creates job `20260928-015439-696f6a3d`, trimming source frames 10–100 and retiming at 1.5x. All 61 decoded output poses match the requested source-frame mapping, and the original intent remains byte-identical in its package. A new Godot audit verifies both source and edited clips, totaling 181 actor-frames. The changed timing requires independent motion-quality review; these tests establish provenance, edit/export preservation and engine import only.

Earlier exports and existing portable installations are not rewritten. This feature is active in the current local Studio and new packages. Legacy jobs without origin records remain usable with missing provenance; no record is invented. Whole-model capability, grounding, partner contact, held-out evaluation and animator review remain open release requirements.
