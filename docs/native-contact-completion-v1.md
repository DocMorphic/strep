## Constraint interpretation recheck, 2026-10-15

NVIDIA's [constraint documentation](https://research.nvidia.com/labs/sil/projects/kimodo/docs/user_guide/constraints.html) describes full-body input rotations as a way to derive constrained joint positions, rather than exact local-rotation constraints. SOMA constraints displayed on 77 joints are converted to the reduced 30-joint representation before model input. Its end-effector interface constrains joint positions and global rotations; this does not establish a material skin-vertex contact guarantee.

The [best-practices page](https://research.nvidia.com/labs/sil/projects/kimodo/docs/key_concepts/limitations.html) recommends fewer than twenty constrained frames per type except dense root paths, and notes that model output can skate or miss constraints. The [published RP-v1.1 model card](https://huggingface.co/nvidia/Kimodo-SOMA-RP-v1.1) still describes single-character output without scene-object awareness.

These sources support retaining separate skin/partner checks and comparing finite correction or scene-conditioned proposals. They do not isolate the cause of this particular hand gap, establish the anatomical correctness of the chosen vertex, or qualify a learned editor. This recheck changes no pinned checkpoint, code, acquisition, training-data rights or held-out reservation.
