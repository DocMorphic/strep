Private trial schemas, unverified jobs, altered files and approval-bearing receipts reject. The local API accepts only the source ID and a bounded step count. Preparation snapshots the saved starting GLB and binds the source, request, recipe and orchestration methods. The driver then performs three sequential supervised phases: freeze recorded methods, propose a correction, and replay every returned export and retention decision. Each uses the prepared offline uv/Python environment, the existing 2,048-MiB admission estimate, 15-second stable headroom, 600-second admission wait and 900-second execution guard. Numerical workers share the project's OS lock. Every terminal resource trace, including failures and deferrals, is replayed and retained.

The runtime manifest is separately bound after creation; its SHA256 is included in guarded run/audit arguments. The bootstrap checks that external digest before and after execution. A changed runtime cannot become a replacement motion reference. The optional digest argument preserves earlier direct CLI usage; Studio always supplies it.

Post requests require an exact loopback host/origin, JSON content type, bounded explicit length, finite values and distinct keys. Source/job/review routes are exact and file serving exposes only the four reviewed downloads after complete bound correction/replay evidence. Failed, deferred, interrupted or changed jobs expose no candidate downloads. PID plus OS birth identity distinguishes live launch/driver processes from dead or reused PIDs; read-only status projection retains raw pipeline files.

This version accepts standard restoration parents only. New continuation outputs and the earlier private 35/12 result do not automatically become new source epochs.
