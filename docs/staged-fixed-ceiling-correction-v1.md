## Explicit fixed-ceiling solver

`scripts/native_component_trajectory_fixed_ceiling_step.py` is a separate opt-in solver. Both material ceilings are mandatory finite numeric inputs, bounded to 0–100 mm. Booleans, missing values, nonfinite values and invalid bounds are rejected. The caller authenticates their original source; the solver explicitly reports that it has not verified ceiling provenance.

An anchor above either supplied original ceiling stops before solving. Every represented conic and strict ray uses those supplied ceilings, including when a later anchor has headroom. Limits are never recomputed from the staged pose. Native norms, cumulative edits, local trust, parameter equalities, full-mesh guards and each initially clear component pair stay hard; objective slack applies only to colliding component guidance. All candidate solver statuses remain visible, with no claim of verified optimality.

All **24 new tests and 83 relevant regressions pass**, 107 total without skips. Tests demonstrate retained original headroom after an anchor changes, strict triangle and containment limits in both conic and ray checks, rejection of an anchor one Float64 neighbor above a limit, invalid ceiling rejection before solving, the complete clock and late clear samples, explicit zero ceilings and unchanged original API behavior. The first test receipt is retained; one fixture initially failed to reduce every maximum triangle row and was corrected before the passing receipt.

The original one-pose and empirical-margin solvers are unchanged. Old empirical margins are not assumed valid for a new pose or material model. All affine proposals require actual stored-export, reference, contact, material, clearance and full-scene validation.
