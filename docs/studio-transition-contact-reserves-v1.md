# Studio contact reserves and candidate bundles

Studio can create and review reserve-guided corrections from the existing shared-transition channel editor. Reserves tighten solver targets while original contact limits, source motion caps, boundary guards and geometry conditions remain binding. This uses the [offline reserve workflow](reserve-guided-transition-workflow-v1.md); the earlier numerical/Studio producers remain unchanged.

## Authoring and review

1. Load a sealed transition in the shared-transition correction editor and save the desired characters' channels, timing points and edit bounds.
2. Open **Contact reserves and candidate export**, then load the original contact limits. Choose existing world, object or partner contacts and save explicit reserves in micrometres. Each reserve must be positive and smaller than its original position limit; no reserve is chosen automatically.
3. Optionally start from the completed correction reviewed above. Its sealed source, permissions, geometry and query budget must match. Controls initialize a new epoch; iteration counts and approval are not inherited.
4. Generate a separate candidate, refresh jobs and review it. Original-source checks and candidate checks are displayed together. Failed conditions remain visible even when an export completes.
5. Download the candidate bundle or individual appended GLBs and tracks. The original scene stays selected. This path exports candidates directly; it does not silently Apply them through the older scene builder.

The source routes are `/api/native-transition-contact-fit-catalog`, `/api/native-transition-contact-fits`, `/api/native-transition-contact-fit-jobs` and `/api/native-transition-contact-fit-review?id=...`. Published downloads use the contained `native-transition-contact-fit-jobs` namespace and an exact allowlist. Existing loopback Host/Origin/JSON gates and single-worker admission remain. The backend validates and snapshots the recipe, reserve and optional seed, then replays the candidate and bundle before returning a completed review. A changed selection cannot reuse a stale UI response.

## Bundle contract

The ZIP contains self-contained `candidate/` scene/GLBs/native tracks plus `history/` request, recipe, seed, reserve binding, original source-rate caps, every raw optimizer probe, selected original-transition snapshots and complete current producer source snapshots. The complete member population and each byte hash are checked against the verified local proposal. Package decisions preserve failed checks and explicitly disallow quality, training, release and engine-playback approval.

Root motion remains embedded in the animation; the exported root track is a reference and must not be applied a second time. Gameplay markers remain unconfirmed and do not authorize runtime dispatch. Historical absolute paths are provenance references: external parent source graphs and numerical runtime dependencies are not bundled, so this is not a standalone solver reproduction archive. A 768 MiB / 4,096-member material budget rejects oversized packages without truncating history. Existing 96-control / one-million-query proposal limits also remain.
