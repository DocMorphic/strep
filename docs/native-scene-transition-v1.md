# Shared native scene transitions

`scripts/native_scene_transition.py` assembles completed actor transition variants into a shared scene with rigid object motion, contact intent, gameplay markers and root references. It accepts arbitrary supplied clips and named participants. Action families are not a whitelist. Original scenes, clip libraries, transition failures and assets remain immutable. This is an offline CLI feature; Studio integration remains open.

## Inputs and output

A recipe binds exactly two `strep-native-scene-contacts-v1` scenes and their `strep-native-scene-game-tracks-v1` requests by SHA256. Every named actor must supply a completed `native_rig_transition.py` or `native_transition_root_support.py` folder with an exact result hash. Necessary root-support conflicts have no candidate and reject assembly. Attempted variants with failed declared measurements can be assembled, but their failures remain in the resulting decision.

Each actor's source GLB library and selected clip indices must match its two source scene entries. All participants must share exact source cuts, serialized bridge endpoints and output duration. Source placements must agree; alignment is an explicit earlier operation. Different actors may use different supplied rig libraries, but one actor's two clips must use the same library. Source root choices must match the selected transitions. Object names and primitive geometry must agree across the two scenes. Existing schema limits remain: 1–8 actors, at most 32 objects, 64 contacts, 128 markers, 30 seconds and 3,601 keys per object.

Run `python scripts/native_scene_transition.py scene-transition-recipe.json reports/my-scene-transition` using the existing NumPy/SciPy environment and a fresh output directory. Recipe fields are:

| Field | Required contents |
| --- | --- |
| `schema` | `strep-native-scene-transition-v1` |
| `sources` | Two `{scene: {path, sha256}, game_tracks: {path, sha256}}` entries |
| `actors` | Every named actor mapped to `{kind, folder, result_sha256}`; kind is `transition` or `root-support` |
| `bridge` | Explicit `contacts` and `markers` arrays using existing scene/game schemas and absolute output seconds |
| `object_limits` | `curve_control_rotation_degrees`, `position_error_m`, `basis_error`, `linear_boundary_jump_m_s`, `angular_boundary_jump_degrees_s`, `acceleration_m_s2` |
| `floor` | `null`, or `{height_m, maximum_penetration_m}` for a whole-scene horizontal plane screen |
| `maximum_timestamp_rounding_s` | Explicit 0–`1e-4 s` permission for second-segment Float32 timing |
| `maximum_pose_vertex_queries` | Integer 1–1,000,000; complete populations reject rather than truncate |

Paths are relative to the recipe directory. Object curve controls must stay within 170 degrees; all other object limits are explicit finite values from 0 through 10,000 in their named units. Floor height accepts −100 through 100 m and penetration limits 0 through 0.1 m. These are request bounds, not recommended quality thresholds.

The output includes copied actor GLBs under `actors/`, a compatible `scene.json`, `game-tracks-request.json`, measured `contacts.json`, non-dispatchable `events.json`, `roots.json`, complete contact observations, and source/method snapshots with replayable decisions. Actor GLBs retain every original clip and the selected transition variant byte for byte. Root references contain every actor's world root matrix and initial-local delta on the same complete clock. Root motion stays embedded in the clips; references must not be applied as an additional placement track.

## Timing and annotation rules

The first source contributes `[0, first_cut]`; the second contributes `[second_cut, source_end]` shifted after the serialized bridge end. First-segment seconds remain exact. Second-segment times use the same Float32 shift convention as native actor transitions; every mapped time and its rounding error is recorded against the explicit permission. Distinct object key collisions and holds collapsing to a point reject. No frame-number or 30 FPS assumption is introduced.

Every source contact and marker gets a mapping disposition. Holds are intersected with retained intervals and retain their original target, correspondence, reduction and limits. Positive-width holds stay holds; a hold reduced to only one boundary point is dropped rather than silently converted into a touch. Point contacts and markers exactly at a retained cut remain at their respective bridge endpoints. Trimmed-away annotations are listed rather than erased from history. IDs receive `first_`, `second_` or `bridge_` namespaces; IDs exceeding the existing 64-character rule reject without shortening.

Contacts across the bridge must be supplied explicitly. Empty bridge arrays mean no new intent was supplied; they never imply that the old grasp/support continues. World, object-local and partner-vertex target semantics remain unchanged. No inferred attachment, grasp, high-five or physical reaction is created.

All transferred gameplay confirmations are reset. Newly supplied bridge markers must also be unconfirmed. The existing event planner orders contact endings, contact starts/touches and gameplay markers at exact shared sample times. Contact boundaries remain non-dispatchable even when their numerical measurement passes. A later explicit timing-review step is needed before gameplay dispatch. Source confirmations remain recoverable in the mapping ledger.

## Object interpolation and measurement

Retained source prop motion uses its original linear-position and spherical-linear-rotation interpolation. SciPy describes Slerp as shortest-path rotation with constant angular velocity between neighboring keys ([SciPy 1.15.3 documentation](https://docs.scipy.org/doc/scipy-1.15.3/reference/generated/scipy.spatial.transform.Slerp.html)). The new bridge uses the existing Hermite translation and spherical Bezier rotation construction with incoming/outgoing object-key rates. Static props use zero endpoint rates. An object may move between different static source placements through a bridge; this does not create physical ownership or attachment.

Object bridge sampling starts on the actor bridge clocks and refines only intervals that miss authored position/basis limits at quarter/mid/three-quarter points. Up to eight refinement rounds are proposed, with a hard 3,601-key schema cap. Refinement never relaxes a tolerance. A bounded proposal that remains inaccurate yields a failed candidate; excessive complete key/query populations reject. An independent readback compares the assembled object's actual linear/Slerp interpolation against the intended source/bridge transforms over the entire declared clock, including contact frame phases. Neighboring-key seam jumps and bridge acceleration are separately measured under the original object limits.

The complete scene clock combines actor native/quarter/mid/three-quarter probes, object keys and quarter points, annotation boundaries/markers, and every predeclared contact velocity population. The population cap counts `queries * (sum(2 * actor_node_count + actor_vertex_count) + 2 * object_count)`. Inputs validate before output. Full actor meshes are used for an authored whole-scene floor screen; missing floor input remains explicitly unavailable. Object/partner contacts are remeasured in the assembled scene using the existing frame-phase contract. Full scene/self/object collision, continuous contact, dynamics, semantics and production motion quality remain unverified.
