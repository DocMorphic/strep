# Bounded vertical-root proposals on native animation keys

`scripts/native_vertical_root.py` proposes world-vertical root edits for an existing rigged clip. It addresses measured floor errors after native rig transfer without changing the source model, action, rig proportions, horizontal path, rotation tracks or native key times. It is an optional correction primitive, not a general contact or realism solver. Action names are never used as a whitelist.

## Authoring and preservation contract

The `strep-native-vertical-root-v1` recipe binds the original GLB by path, SHA256, explicit animation index and skin root node. It also binds an original `strep-rig-floor-comparison-v1` receipt by path, SHA256 and `source`/`target` side. The receipt must describe that same GLB/index and include every original animation key and midpoint, both endpoints and all twelve 30/60/120-Hz phase populations. Every loaded mesh vertex is evaluated in the final comparison. Receipts are measurement inputs, not quality approvals.

Set `maximum_displacement_m` explicitly, greater than zero and at most 0.22 m, with a nonnegative `floor_reserve_m` strictly smaller than the original floor tolerance. Declare at least one distinct `frozen_keys` index on the root translation track. The development study freezes the final key; it deliberately permits an adjusted starting height. Frozen samples on every other track remain exact. This is not a claim that a transition into the adjusted start remains compatible.

The supported source has one existing LINEAR root translation channel, a rigid static ancestor transform, and the complete skin beneath the selected root. Every vertex must have a finite positive vertical translation response. Stored inverse-bind roundoff can make that response slightly different from one; guidance uses the minimum response conservatively over the complete mesh. Animated ancestors, partial-skin roots and nonpositive vertex response require another representation and are rejected.

The proposal preserves all source payload and animations and appends a separate editable animation. The original stays selected, including for sampled-passing proposals. The tool records exact inputs, implementation copies/digests, dependency versions, sparse constraints, source observations, controls, serialized motion and geometry observations. Fresh output folders are required; failed attempts remain separate.

```powershell
python scripts/native_vertical_root.py recipe.json fresh-proposal
```

Use the existing resource-admitted, single-thread guarded worker for numerical jobs on this machine. No inference model or checkpoint download is required for this primitive; it uses the pinned model-free source dependencies.

## Motion constraints and storage modes

Original positional speed/acceleration and angular speed/acceleration are measured at uniform 120-Hz times through the clip. Each joint keeps its original maximum in each of four equal-duration bins, with the existing `1e-5` numerical tolerance. Every supplied joint and rate row participates; this is a new declared correction contract, not a claim that every historical study used these bins. Frozen keys, a nonnegative vertical edit and the explicit maximum displacement remain hard acceptance conditions.

For a shared vertical derivative, each original 3D positional norm ball intersects the world-Y line in an interval. Intersecting those intervals over all joints is an exact scalar reduction in ordinary Float64 arithmetic. The sparse model couples every native root key using the actual native sampler's interpolation and endpoint branches. Angular motion is unchanged but is still remeasured from the exported file.

`storage_mode` is optional and defaults to `continuous`: a HiGHS LP proposes real-valued offsets, then the actual Float32 GLB is checked. Solver success alone never accepts an export.

The explicit `float32-axis-grid` mode applies only when world vertical maps to exactly one signed unit local root axis. It uses a HiGHS mixed-integer model to choose representable Float32 coordinates directly. Each unfrozen key receives a power-of-two grid sufficient for its entire declared displacement range, including exponent crossings. Frozen keys retain their original stored values. This grid is sufficient, not an exhaustive enumeration of every possible Float32 value, so failure cannot prove that no stored-key correction exists. A stricter `1e-8` model-row reserve protects numerical arithmetic; final rate, displacement and geometry acceptance are unchanged. The solver is bounded to 60 seconds and one thread. A time limit or unsuccessful solve produces no adopted candidate. General rotated root axes need another storage model.

Final acceptance recomputes the complete original floor clock, all four rate populations, displacement, horizontal preservation, frozen root keys and all other native tracks from the exported GLB. Horizontal drift has an explicit `1e-7` m readback tolerance. The original source floor observations must reproduce exactly. Floor clearance does not establish planted contacts, balance, naturalness, object/partner interaction, continuous collision freedom, engine playback or human approval.

## Retained development evidence

The input is the unchanged seed-77 get-up motion transferred to CesiumMan in the previous 24-case development population. The original target fails 1,473 of 4,292 floor observations, with 131.840662 mm peak penetration. This is a reused development motion and rig, not held-out release evidence.

The first attempt stops before optimization because an unnecessarily strict software precondition requires unit skin response to `1e-10`. All skin joints are affected, but the 3,273 vertex responses range from 0.9999999143183231 to 1.0000000894069672. The positive complete-response model removes that unnecessary unit assumption without loosening the floor, motion or displacement acceptance criteria. A generated-rig regression exercises the nonunit response explicitly. The failed original guard and diagnostic remain preserved.

The continuous attempt produces 717 scalar controls with 7,154 sparse rows covering 54,378 original rate conditions. Exported peak penetration falls to 4.500004 mm and all 4,292 sampled floor checks pass. Maximum joint displacement is 127.340704 mm; ending root key, all other tracks and horizontal joint positions are preserved. However, 28 positional speed and 25 acceleration rows fail, so the export is rejected. The solver has a 9.023e-10 maximum linear violation. Complete independent replay also finds 38 speed and 12 acceleration failures in the unrounded intended motion; therefore storage rounding is not the sole source of disagreement. Native translation storage error reaches 1.482e-8 m. The preserved candidate is diagnostic, never a quality-approved animation.

The independent replay rehashes all 18 archived artifacts and three original input bindings, reconstructs all 4,292 source/output poses and complete floor observations, remeasures every rate condition and checks the entire retained source payload plus frozen/other tracks. Every stored observation reproduces exactly. Actual failed rate excesses are 2.094e-6 m/s and 4.595e-4 m/s² above the original tolerance. The production guard completes in 49.781 seconds with all 51 resource observations replayed; the independent motion/geometry replay completes in 55.750 seconds with all 57 resource observations replayed. No optimizer rerun is used for this replay.

The separate Float32-grid attempt returns solver status 2 (infeasible) for this sufficient grid and stricter numerical model. It exports no candidate. This does not establish infeasibility of all Float32 values, other parameterizations, articulated correction or the requested action. Its guard completes in 55.891 seconds, with all 57 resource observations replayed. The continuous failed export remains retained separately, without replacing the original.

The final targeted batch passes **32 tests in 29.28 seconds**. It covers generated-rig actual export/readback, nonunit skin responses, both successful and frozen-penetration grid cases, exponent crossings, explicit rejection of a rotated axis by the storage model, full-joint norm intersections, native endpoint arithmetic and invalid bindings/recipes. An initial grid-test batch uses an incompatible rotated fixture and fails two checks; those failed records remain saved, and the final batch gives the axis-grid tests an explicitly aligned fixture rather than relaxing the method's axis check. Its guard completes in 45.719 seconds with all 47 resource observations replayed. SciPy's forwarded HiGHS-option warnings remain visible. The full/focused CI inventories include the suite and validate as 503 Python/45 Node and 66 Python/5 Node files respectively; this is inventory validation, not a claim that all suites were rerun locally.

A separate declared population selects **all seven** floor-failing rows from the earlier 24-case study. It fixes the same 0.22 m movement budget, 0.5 mm model floor reserve, frozen final key and storage mode for every case. It reuses the checksum-verified get-up result instead of rerunning it. A necessary bound using the complete positive vertex response can reject an over-budget vertical-root case without invoking an optimizer; that rejection applies only to this edit space.
