# Reusing a complete scene scan for contact forces

`scripts/scene_object_contact_forces_cached.py` runs the existing contact-force assessment with a completed, independently replayed geometry archive. It measures actual supplied-rig contact points, surface normals and relative-speed stencils again, then solves the declared rigid-object forces. It avoids repeating the complete geometry scan or copying its large numeric archive into each force output.

Run the worker through `run_guarded_job.py` with the same full-posed-body resource policy as the ordinary force assessment: 2048 MiB expected RSS plus the default 600 MiB reserve. This path still evaluates full posed skin for contacts. It does not justify a smaller resource profile.

```powershell
uv run --offline --isolated --no-project --python 3.10 --with-requirements requirements-ci.txt python scripts/run_guarded_job.py --worker scripts/scene_object_contact_forces_cached.py --output reports/fresh-force-guard --expected-rss-mib 2048 --stable-seconds 15 --admission-seconds 600 --max-seconds 3600 -- reports/request.json reports/complete-geometry reports/independent-replay.json reports/replay-source.py reports/fresh-forces
```

The request retains the existing `strep-scene-object-contact-forces-v1` schema. Its scene and geometry policy must match the complete scan exactly, including source files, actor assets, policy thresholds and clock. Every COM and surface-contact sample time must already have a geometry observation; missing times are rejected rather than interpolated or silently omitted. A changed candidate requires new geometry evidence unless a separate, explicitly scoped identity proof applies; this runner accepts only the complete archive.

The replay receipt uses `strep-full-geometry-replay-v1` and contains `status: complete`, `validation_passed: true`, `complete_population_replayed: true`, the result/archive/auditor SHA-256 bindings, `sampled_geometry_pass`, and a `population` object containing the exact result topology, object names, sample times, limits, declared planes, aggregate geometry decision and observation hash. The numeric auditor must emit this receipt only after replaying the complete population. The loader verifies hashes and coverage; it cannot authenticate who wrote a receipt or prove that a claimed replay actually executed. Receipt files are evidence within the owned pipeline, not certificates from untrusted uploaders.

All actor/object pairs, actor pairs, declared planes, volume records and degeneracy records must remain present at every time. Before skin queries, reported topology must also match the loaded asset vertex count, complete triangle-index hash and primitive coverage. A successfully replayed geometry failure remains a failure and prevents coupled scene/force success, even if conditional forces alone are feasible. The loader checks original and frozen inputs, producer methods, observation archive and its receipt before work; the runner rechecks these bindings after assessment. Frozen request/assets/methods and external geometry bindings remain in the output protocol. Preserve the external archive and original referenced paths for replay: this is not a self-contained, relocatable package.

This path grants no continuous collision, self-collision, actor reaction/joint dynamics, impact, human capacity, engine or animation-quality approval. Fixture tests exercise cache integrity and real tiny skinned contact/force queries; their synthetic replay receipts are explicitly test fixtures, not independent numerical geometry evidence for a production character. The departure candidate now has a [complete-body development replay](protected-hold-transitions-v1.md); other characters and scenes require their own complete evidence before using this path.
