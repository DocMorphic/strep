# Test contact release timing without weakening the motion checks

The first four completed whole-support corrections have eight foot-speed peaks. Every peak occurs at the final labelled support step, where the fitter changes its anchoring weight from0.75 to0.25. At those exact steps the corrected centroid moves faster than the raw transfer, even in clips whose overall maximum improves. The strongest example is backpedal on rig02: left-foot speed at frame31 rises from0.095342 to0.285625 m/s. Grapevine dance on rig01 shows0.055678 to0.197423 m/s at frame34. These associations motivate an ablation; they do not prove that changing the fade will improve motion.

`reports/support-release-hold-v1/release-diagnostic.json` preserves all eight peaks and binds the four source snapshots. The fixed development population is all four completed cases in `whole-support-breadth-interim-v4`: backpedal on rigs01/02/03 and grapevine dance on rig01. Rig02 backpedal runs first because it has the largest observed speed failure, followed by dance; this is targeted development, never a held-out test.

`reports/support-release-source-proof-v1.json` checks all four prior geometries against their decoded verifications, velocity traces, retained summary and actual engine proofs. It also verifies that the isolated fitter differs from the frozen original only in the declared guide transformation and descriptions. The old objective weights, solver and export path remain identical.

The opt-in `support_release_hold.py` removes only the release fade inside each existing draft interval, retaining its onset ramp, anchor, labels and outside frames. Existing clipped-start/end policies stay intact. Custom weights and overlapping/malformed intervals are rejected. No contact is extrapolated beyond the clip. The isolated `support_release_clip.py` retains the same zero-edit raw initialization, support weight40, curvature weight10, six sweeps and all hard limits. The running broad study's implementation is unchanged.

A sharper release could improve a stance while worsening the following swing. `support_release_metrics.py` therefore decodes actual exported meshes and records full three-dimensional foot-centroid velocity and acceleration. Every observed release includes the last support frame and first three swing frames, clipped to real samples. Direction changes count as acceleration even when speed stays constant. These centroids remain geometric proxies, not anatomical sole contact points or force measurements.

The frozen experiment compares raw input, prior correction and new candidate. It requires no increase over the prior correction in predicted-support maximum/p95 speed, plus maximum speed below `max(0.05 m/s, raw maximum)`. Hover and floor allow at most `max(10 mm, prior hover)` and `max(5 mm, prior penetration)`. Root acceleration, local rotation step, global foot acceleration and every release-window acceleration must not exceed the greater of raw and prior. Existing decoded hard limits and real engine import remain required. All checks and failures are retained separately. These are development screens, not new release approval thresholds.

Twenty tests pass for interval timing, preservation of authored inputs, clipped boundaries, vector derivatives, release windows, malformed inputs and rejection of hidden swing regressions. Numerical success never grants animation-quality approval.

`reports/support-release-hold-v1` has completed backpedal rig02 and is running dance rig01. Its four cases will import all three variants into Godot, for1,980 planned actor-frames. Predicted support, intentional pivots, semantics, anatomy and cleanup time still require independent evaluation.

The first case passes450 actual engine actor-frames and the decoded edit bounds, but fails its frozen numerical screen. Maximum support speed improves from raw/prior0.2090/0.2856 to0.1300 m/s on the left foot and from0.1434/0.2079 to0.0790 m/s on the right. Root acceleration worsens from raw/prior7.4952/11.6733 to12.4829 m/s². Two left-foot release windows and one right-foot window also exceed the larger raw/prior acceleration. The largest left regression is frame32:52.2309/51.0868→54.4211 m/s². Holding the stance more firmly therefore trades sliding for release dynamics; it is not a solved correction.

`summarize_support_release.py` independently recomputes the original comparison function and checks completed artifact, prior-input and engine hashes. `reports/support-release-interim-v1/summary.json` retains all four cases:1 complete,3 unfinished,0 passing among the completed case. The unfinished cases remain in the denominator and the fixed experiment continues unchanged.
