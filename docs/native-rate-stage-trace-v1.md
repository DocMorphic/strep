# Continuous, stored-key and decoded native rate traces

`scripts/native_rate_stage_trace.py` compares one explicitly selected native joint velocity or acceleration row through three stages: the continuous source-relative edit, its Float32-key proxy, and independently loaded candidate curves. It supports all four linear/angular rate metrics and queries only the row's two or three source-rate times. Before those queries it checks the complete static/edit contract, every controlled native key against the supplied controls, unchanged channels and source asset hashes. Candidate mutation during a trace rejects the result. Source-rate caps and tolerances come from the caller's original archive; the trace does not reconstruct or approve that archive's provenance.

The rate calculation uses the original source interval, rather than subtracting two local timestamps again. Local subtraction can differ in its last bits; replacing the source interval would change a tight native comparison. Linear rates use positional differences; angular rates use world-relative rotation vectors and reject ambiguous near-pi steps. The scalar residual subtracts the original cap and existing tolerance separately, matching native acceptance arithmetic. Proper rotations, matching homogeneous poses, uniform support, complete finite observations and finite arithmetic are required. A local row pass never approves a clip: contact, full motion, geometry, import and human-quality flags remain false.

The isolated public-source run passed **99 tests in 20.41 seconds**: **44 new trace tests**, the **34 ledger tests**, and the existing native norm checks. Tests compare all four metrics with complete decoded native math, both translation and rotation edits, exact source intervals, entire controlled-key identity, static payload changes, candidate/input mutation, source boxes, unsupported rows, invalid caps, invalid clocks/poses, ambiguous rotations and overflow. The result is `reports/native-rate-stage-trace-source-check-v1/result.json`, SHA256 `14776121aeaea8e4a8d462174dc36b340b6d8670975829f6e734ddb1dff8d688`. No model/vendor payload, GPU render or real engine invocation was used in these fixture checks.

Residuals are normalized, and strictly positive means failed. The retained baseline's continuous edit fails this row, while its stored keys and actual decoding pass. All five later exports fail. Across these eighteen queried times, the stored-key proxy differs from actual decoding by at most `1.2440567926383356e-15 m` in joint position, `1.4432899320127035e-15` in basis components, and `4.007461029686965e-12 rad/s²` in rate-vector components. These are local observations, not full-motion bounds or import measurements.

The native proposal uses continuous derivatives with a decoded anchor. Keeping the baseline's decoded-minus-continuous vector offset constant makes the exact later continuous evaluations pass, just as the affine model predicts. Their normalized residuals differ from the saved affine predictions by only `1.47e-12` to `3.69e-10`; the actual decoded failures are `1.01e-6` to `2.89e-6`. The measured offset changes with each candidate; one component changes by as much as `0.00028503526740220053 rad/s²` relative to baseline. For these samples, the stored-key rounding variation explains the missed native decision far more than the error from linearizing the continuously reanchored vector. The trace does not prove a uniform quantization bound, global feasibility or the behavior of other rows/directions/rigs.
