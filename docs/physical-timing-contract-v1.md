# Explicit physical ownership timing

The grip editor now lets an author request a maximum delay for physical grab, release and handoff transactions. **Maximum physical delay (ms)** is optional; zero requests exact timing. **Check timing** reports the largest predicted delay and any distinct changes to the same prop that collapse onto one physics tick. It is a preflight calculation, not a simulation or realism rating. Editing the selections clears the result; late responses cannot certify a changed request.

Command-line requests can include a nonnegative finite Float64 limit in seconds:

```json
"maximum_application_delay_s": 0.016
```

An omitted field preserves the legacy compiled configuration and startup bytes. An explicit invalid value is rejected. Authors can choose a limit larger than one step; this neither increases the engine's step delay nor relaxes any existing quality gate. Supported rates remain 60, 120 and 240 Hz. Zero rejects even a source timestamp one floating-point step after an engine boundary. No timestamp is rounded, moved or removed.

The compiled `physical_timing` report retains the selected limit as eight little-endian Float64 bytes, the complete ordered source/application/delay triples as binary bytes, and each ownership group's first applicable tick. The tick is the first integer whose represented `tick / rate` is at least the represented source time. Correcting both neighboring ticks avoids treating rounded multiplication as an exact clock. Two distinct groups changing the same prop on one tick reject regardless of delay tolerance. Different props can share a tick; an atomic multi-prop or handoff group remains one transaction.

Python reconstructs the whole source-bound ownership plan at export. Godot independently reconstructs the report and rejects changed, missing, falsely approved or inconsistent timing fields **before importing actors or installing bodies**. During playback, a transaction must occur on its declared tick. The offline editable bake independently checks the complete actual action clock against the limit. Its downloadable `bake-audit.json` retains the full requested timing report as well as actual delays. Original actor, mesh, source marker and contact-intent bytes remain unchanged. Complete older Studio archives without this optional contract remain replayable; new workers and explicitly timed jobs require the helper source and recorded hashes.

This covers ownership transactions on the runtime's nominal finite physics clock. It does not bound rendering latency, wall-clock latency, arbitrary gameplay events, network timing or contacts in another world. It does not implement fractional engine steps. Matching an authored tolerance is separate from the retained **exact physical timing** result and from visual/physical contact quality. No animation or release approval follows from a successful export.
