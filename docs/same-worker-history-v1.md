# Reuse verified contact history within one worker

Contact batches previously reconstructed every saved trial and complete interval in every ancestor before each new window. The growing replay cost made longer correction studies expensive even when those exact states had already been checked in the same worker. Batches now own one `IntervalReplaySession` that keeps only the last fully verified state.

A fresh worker still performs full native replay. A new state also receives complete local proposal, saved-motion, geometry, whole-interval and original-row preservation checks. Reuse applies only to a previously verified ancestor within that same sequential batch. It never loads an attestation or cached state from disk. Standalone interval repair continues to use full replay by default.

Each reuse rehashes every recorded artifact and original input, including all ancestral protocols/results, trial motions and audits, streamed proposals, interval observations, source references, skeleton metadata and archived implementations. Current implementation bindings are also checked. The context includes the exact original pose bytes, array shapes and precision, study, frames/width, original bindings, metadata and origin implementation. Changed context is rejected and requires a fresh session. The original owned factory remains fixed; a later call cannot replace it with a different callback.

Cached arrays, controls, receipts and binding maps are copied before returning them. Caller edits cannot change the next reuse. Full ancestry still counts toward the original 32-stage limit, including cached nodes, and cycles remain rejected. A failed new stage cannot replace the previously verified state. The session retains one state rather than accumulating all prior poses or solver objects.

Receipts explicitly label reuse as `same-worker-bound-reuse` with `geometry_replayed_this_call: false`. Batch protocol, progress and results expose the policy and counters for complete native replays and reused histories. These counters describe executed software paths; they are not contact, motion-quality or release certificates. Every original physical tolerance and retention gate remains unchanged.
