# Cycle crossfades and latest-transition reversal

The exported Godot runtime now includes a controller for switching between two cycle clips on the same rig. It uses two hidden donor skeletons and one visible output skeleton, interpolates local bone transforms, aligns the incoming pelvis at transition start and reports full root movement or right-composed deltas. Rig compatibility, explicit event policy and exclusive animation ownership are required. Setup is in [the integration instructions](../integrations/godot/BLENDS.md).

The controller chooses events at their actual crossing time, rather than at the end of an update. `dominant` transfers ownership at the halfway point, including the exact tie on the incoming side; `incoming` selects the target throughout; `silent` suppresses both through the inclusive blend end. Subsequent target markers resume normally. Source identity and weight accompany the original authored payload. These policies do not undo gameplay effects or establish grasp/contact correctness.

`reports/runtime-crossfade-v3` verifies three cases: distinct 45- and 60-frame clips in both orders on a 65-bone rig, plus different phases on a second, 19-bone rig. Both root modes, all three event policies and half-frame, seven-frame and whole-interval updates are included. All **54 runs, 3,492 pose samples and 546 marker crossings** pass. Actual Godot bone transforms and CPU-skinned positions are compared to independently sampled glTF motion, local TRS interpolation, root alignment and a frame-domain event oracle. Exact-halfway simultaneous markers, silent starts, invalid durations/policies/updates, active-blend replacement and incompatible rigs are checked.

Maximum bone matrix error is 1.1144e-5, root matrix error 5.8920e-6, and CPU skin error 1.1221e-5 m. The original v1 engine output is retained with a failed verifier: it incorrectly assumed glTF node indices were parent-first. The repaired recursive hierarchy calculation passes node-renumbering tests and verifies that original output in v2. The final v3 rerun adds incompatible-rig rejection and passes with matching implementation hashes. Twenty-seven focused cycle, reverse, blend-oracle, event and loop tests pass.

The actual Studio event-only export `20260928-001231-f7bcda81` preserves the source and repeated GLBs and root track. Its package contains 150 source-backed files, including the new adapter, instructions and implementation snapshot. Existing cycle downloads and both new crossfade downloads match local/package bytes; see `reports/runtime-crossfade-export-v1/verification.json` and `crossfade-verification.json`. New cycle exports include the files and explicit metadata; already-created offline copies retain their older frozen contents.

The follow-up `reports/runtime-chained-blends-v1` verifies three successive handovers with reused donors and changing policies, preserving one fixed output anchor and cumulative root placement. All **18 runs, 54 handovers, 1,722 pose samples and 252 marker crossings** pass. Each marker callback also attempts a reentrant advance; all 252 attempts are rejected. Starting another blend preserves every displayed bone, root transform and event count. Independent calculations cover fine/coarse updates, both root modes and both rigs. Maximum bone/root errors are 1.5756e-5/9.0584e-6, with CPU skin error 1.6042e-5 m. No runtime source change was needed for these additional checks.

This is two-clip runtime integration, not contact fitting or animation-quality acceptance. Older transition history, interruption into a third clip, actual game state/physics, GPU rendering, held-out pairs and animator review still need evidence. The two source clips can produce a mathematically consistent blend that slides, penetrates or looks implausible. No release gate is approved.

Primary API references: [Godot Skeleton3D](https://docs.godotengine.org/en/4.7/classes/class_skeleton3d.html) and [Transform3D interpolation](https://docs.godotengine.org/en/4.7/classes/class_transform3d.html#class-transform3d-method-interpolate-with).

## Reversible latest transition

The controller now retains the last outgoing donor, source origins and alignments after handover. It can rewind from later target playback through that transition and replay it forward. Starting a subsequent transition establishes a new history boundary. Both donors must remain alive; requests before that boundary fail without mutation. Reverse events are silent by default and use a separate `marker_reversed` signal when requested. They do not undo gameplay.

`reports/runtime-reverse-blend-v3` passes **144 runs, 2,232 pose samples, 1,984 forward crossings and 764 reverse crossings**. Coverage includes two rigs, both orders of distinct clips, both root modes, three event policies, silent/notifying reverse, coarse updates, partial reversals, midpoint/end/start destinations and forward replay. All 764 reverse callbacks reject reentrant movement and transition calls. Maximum bone/root matrix errors are 1.9610e-6 and 1.1661e-6; CPU skin error is 1.9799e-6 m. The verifier uses independently decoded glTF poses and frame-domain crossing rules.

The failed v1/v2 audits remain retained. They exposed duplicate or omitted exact-boundary events when independently accumulated donor seconds were reversed. The controller now uses one compensated transition frame clock. Explicit `advance_frames`/`rewind_frames` methods preserve exact integer and half-frame authoring intervals; seconds-based updates retain their represented floating-point timing without epsilon snapping. The successful study separately tests exact frame destinations and ordinary seconds destinations. This is an API distinction, not proof that every seconds conversion lands on the corresponding exact frame. Twelve focused cycle/oracle/source-rejection tests pass.

The updated forward regression `reports/runtime-crossfade-v4` also passes. A real Studio export, job `20260928-010101-4a24476b`, includes the new adapter, methods, history limit, documentation and source snapshot. All 150 source-backed archive entries, both unchanged animation GLBs, root track and six HTTP downloads match their retained evidence in `reports/runtime-reverse-blend-export-v1`. Existing offline copies remain unchanged. The updated chained-forward regression `reports/runtime-chained-blends-v2` passes all 18 runs, 54 handovers, 1,722 pose samples and 252 marker crossings/reentrant rejections. No quality/release gate is approved.
