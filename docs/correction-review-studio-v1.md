# Audited correction review in Studio

Open Characters → Review corrected motions in Studio. The panel presents the completed angular-chain development run, including all three corrected cases, the contact-failing rig02 case and the already-passing control. The control repeats the dance clip; this is not five independent motions or new held-out coverage.

The version selector offers raw transfer, the input before angular correction, and a corrected candidate when the chain actually passed. It defaults to the retained input. Case outcomes and selected-version labels are separate. For the contact-failing case, the panel names both unresolved foot-release acceleration checks and offers no corrected version. The normal imported-character selector and editing jobs are unchanged.

The preview displays the actual supplied rig with a neutral grey material. It preserves frame and camera when switching versions, follows horizontal root movement, supports scrubbing/playback and stops at the final frame. Each GLB is checked against its package hash before rendering. Stale asynchronous loads cannot replace the selected clip. Loading clears old metrics and hides the old rendered clip; a load or hash error cannot masquerade as the requested version. The panel also handles being opened before module initialization finishes.

Each case has a comparison ZIP containing the retained GLBs, root tracks, contact estimates, audit, measurements and rig license/provenance files. `scripts/package_correction_review.py` checks the independent chain audit and all completed source outputs before packaging. Failed/ineligible or partial outcomes never gain a corrected export. `reports/rig-jobs/correction-review-v2/package-verification.json` binds all packaged files. The first package attempt is retained in correction-review-v1: its label lookup incorrectly expected `motion.action` instead of the actual frozen `motion.case` field. No catalogue was published for that attempt.

The server serves all five cases,13 GLBs and15 package/audit/license links successfully; every downloaded GLB matches its expected hash. Evidence: `reports/correction-review-http-v1.json`. Each of the five ZIP archives was reopened and every member compared against the packaged files. Three focused package tests pass, including stale-source rejection and prevention of corrected exports for failed outcomes.

Browser verification covered actual grey-character rendering, dance terminal frame209, corrected/raw switching at frame60 on the larger rig, playback advancing from0, scrubbing to60 and stopping, failed-case version exclusion, and visible numerical/quality limitations. Larger GLBs caused some browser-automation observation timeouts; subsequent accessibility observations and screenshots confirmed the selected clip loaded correctly. This is interface verification, not independent animator review.

Sources: `scripts/correction-review.{html,js}`, `scripts/character-studio.{html,css}`, `scripts/build_desktop.py`, and the generated `scripts/action-studio.html`. The running Studio service was not restarted; it serves the rebuilt HTML from disk. Model, solver and ongoing worker dependencies are unchanged.

Scope remains a review/export bridge for this audited development run. Users cannot yet submit arbitrary uploaded clips to the angular chain through this panel. Numerical checks, tolerated penetration, unconfirmed support labels and rotation-tail regressions remain visible limitations. The project-wide goal stays active; broader contact/partner reliability, generic workflow integration, held-out evaluation and independent cleanup-time evidence are unfinished.
