# Explicit processing budgets for character correction

Two complete-clock humanoid trials reached the Studio correction worker's 900-second execution limit during the first proposal's geometry audit. Both retained their completed original audit and attempted clip, but neither produced a completed proposal decision. Fixing late numerical-library imports corrected thread configuration without making this workload fit the 15-minute budget.

The second run reproduces all 2,017 original geometry records after rebinding copied source paths. Every observation-array payload hash matches, as do the first proposed GLB, decoded constraint arrays and contact measurements. The hand gap remains 25.350 mm against the 5-mm limit. This is repeatability evidence, not acceptance of the proposed motion. Each failed resource trace replays all 904 observations.

Studio now exposes a processing-time limit of 15, 30 or 60 minutes, defaulting to 60 in the editor. Older requests with no setting retain their 15-minute default. The chosen integer `max_runtime_seconds` is saved in the request, checked against its original hash before launch, passed to the real supervisor policy, and returned with that job's status. Changing the editor setting during saved-scene validation prevents a stale submission. Refresh displays the saved job's budget, independently of the current editor choice.

The global resource policy is unchanged: its maximum execution allowance remains one hour. The correction keeps a 512-MiB expected/maximum process tree, 600-MiB free-memory reserve, 15-second stable admission and 600-second admission timeout. More processing time does not alter contact limits, geometry predicates, sample populations, permitted tracks, solver iterations, original selection or quality/engine/release approval. It does not provide resumable correction yet; interrupted proposals remain incomplete.

All 89 focused Python checks pass, including actual supervisor-policy forwarding, legacy defaults, immutable queued budgets, invalid values, saved-job status, worker thread configuration, scene/correction integration and preview checks. The final Node editor test separately verifies each offered budget, invalid inputs, async setting changes and saved-job status. An earlier editor-input snapshot is retained; only the final editor checks were repeated after its status text changed, with every Python and HTML input verified unchanged.
